# cfDNA Feature Extraction

This folder contains the R scripts used to process BAM files generated by the upstream cfDNA sequencing analysis workflow and extract cfDNA-derived features for downstream machine learning analysis.

The scripts can be used as a complete workflow through `cfDNA_calling.R`, or individual components can be run and modified separately when alternative inputs, parameters, or feature-extraction strategies are required.

## Workflow

```text
Upstream cfDNA sequencing analysis
                |
                v
            BAM file
                |
                v
      +-------------------+
      | BAM preprocessing |
      | read_bamfile.R    |
      +-------------------+
                |
        +-------+-------+
        |       |       |
        v       v       v
   Fragment   End     Tumour
    length   motifs   burden
        |       |       |
        +-------+-------+
                |
                v
       Feature integration
          BAM_RDS.R
                |
                v
        cfdna_df (*.rds)
                |
                v
            Rscript-ML
```

## Script Overview

| File                      | Description of job                                                                                     | Main result                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| `cfDNA_calling.R`         | Main workflow that coordinates BAM reading, cfDNA analysis, feature extraction, and output generation. | Complete cfDNA feature dataset               |
| `getPath_BAM.R`           | Locates the input BAM file and determines the sample name from the input directory structure.          | `bam_file_path`, `user_filenames`            |
| `read_bamfile.R`          | Reads and filters BAM alignments and creates the `SampleBam` objects required for downstream analysis. | `sample.bam` and strand-specific BAM objects |
| `utils.R`                 | Provides supporting functions for genome binning, chromosome information, and bias correction.         | Utility objects/functions                    |
| `ichorCNA.R`              | Reads the ichorCNA parameter file and extracts the estimated tumour fraction.                          | `tumor_fraction`                             |
| `cfdna_feature_1.R`       | Extracts fragment-length features from the genome-wide fragment-size distribution.                     | `isize_peak`, `isize_label`                  |
| `cfdna_feature_2_motif.R` | Extracts 5′ and 3′ end-motif features from cfDNA fragment sequences.                                   | Motif features                               |
| `BAM_RDS.R`               | Combines all extracted features into one data frame and saves the result as an RDS file.               | `cfdna_df`, `.rds` file                      |

R 4.4.3

## Getting Started

A user who wants to reproduce or modify this workflow should start with package installation before running the scripts.

### 1. Install R Packages

Install the required packages in R.

For example:

```r
install.packages(c(
  "Rsamtools",
  "GenomicRanges",
  "QDNAseq"
))
```

Install Bioconductor packages using:

```r
if (!requireNamespace("BiocManager", quietly = TRUE)) {
  install.packages("BiocManager")
}

BiocManager::install(c(
  "Biostrings",
  "Rsamtools",
  "GenomicRanges",
  "QDNAseq"
))
```

Install `cfdnakit` according to the package installation instructions used for the project.

After installation, verify that the required packages can be loaded:

```r
library(cfdnakit)
library(Biostrings)
library(Rsamtools)
library(GenomicRanges)
library(QDNAseq)
```

> **Note:** Package versions can affect reproducibility. The versions used for the original analysis should be retained when exact reproduction is required.

## Input Data

### BAM Files

The primary input is a BAM file generated by the upstream cfDNA sequencing analysis workflow.

The expected directory structure is based on the configuration in `getPath_BAM.R`.

Users should modify:

```r
user_directory <- "path/to/your/bam/file"
```

to point to their own input directory.

The script then:

1. Searches for subdirectories under the specified directory.
2. Identifies the most recently modified directory.
3. Uses the directory name as the sample name.
4. Searches for BAM files within that directory.
5. Creates the BAM file path used by the downstream workflow.

Therefore, users with a different directory structure may need to modify `getPath_BAM.R`.

## Recommended Full Workflow

For users who want to reproduce the complete feature-extraction workflow, `cfDNA_calling.R` is the main entry point.

### 1. Configure the Input Path

Open:

```text
getPath_BAM.R
```

and modify:

```r
user_directory <- "path/to/your/bam/file"
```

### 2. Check Genome and BAM Parameters

The default BAM-processing parameters are defined in `read_bamfile.R`:

| Parameter    | Default |
| ------------ | ------- |
| Genome       | `hg19`  |
| Bin size     | `1000`  |
| Minimum MAPQ | `20`    |
| Blacklist    | `FALSE` |

Modify these parameters if your analysis requires different settings.

For example:

```r
read_bamfile(
  path,
  binsize = 1000,
  genome = "hg19",
  min_mapq = 20,
  apply_blacklist = FALSE
)
```

### 3. Configure the Output Path

Open:

```text
BAM_RDS.R
```

and modify:

```r
saveRDS(
  cfdna_df,
  file = "path/to/your/RDS/file"
)
```

The output path should point to a location where the user has write permission.

### 4. Run the Main Workflow

Run:

```r
source("cfDNA_calling.R")
```

The main script loads the required supporting scripts, processes the BAM file, extracts the features, combines the results, and saves the final RDS dataset.

## Running Individual Components

The scripts are separated by function so that users can modify or reuse individual parts of the workflow.

This is useful when:

* using a different BAM file structure;
* changing BAM filtering criteria;
* changing genome or bin-size settings;
* extracting only selected feature groups;
* replacing a feature-extraction method;
* testing an alternative feature definition;
* changing the output format;
* debugging a specific processing step.

### BAM Reading Only

If only BAM preprocessing is required, `read_bamfile.R` can be loaded independently together with its utility functions.

The user can then call:

```r
source("utils.R")
source("read_bamfile.R")
```

and provide a BAM path directly:

```r
sample.bam <- read_bamfile(
  path = "path/to/sample.bam",
  binsize = 1000,
  genome = "hg19",
  min_mapq = 20,
  apply_blacklist = FALSE
)
```

This allows users to change BAM-processing parameters without running the complete feature-extraction workflow.

### Fragment-Length Analysis Only

`cfdna_feature_1.R` can be used when the user already has a suitable `sample.bam` object.

The script extracts:

* `isize_peak`
* `isize_label`

The short/long classification used in the current implementation is:

```text
isize_peak <= 150 bp  -> short
isize_peak > 150 bp   -> long
```

The short-to-long fragment ratio is calculated separately during the main workflow.

Users can modify this script if they want to use a different fragment-length threshold or alternative fragment-size features.

### End-Motif Analysis Only

`cfdna_feature_2_motif.R` can be used when a suitable BAM-derived object containing fragment sequences is available.

The current implementation:

1. Separates forward and reverse strands.
2. Reverse-complements reverse-strand sequences.
3. Extracts the first and last four nucleotides.
4. Generates all possible tetranucleotide motifs.
5. Calculates motif frequencies.
6. Identifies the most frequent motifs and their proportions.

The resulting features include:

```text
motif_peak_fwd_*
motif_peak_rev_*
motif_peak_*
prop_fwd_*
prop_rev_*
prop_*
pattern_prop_*
```

Users can modify this script if they want to analyze different motif lengths or alternative positions within the fragment sequence.

### Tumour Fraction Only

`ichorCNA.R` can be used when ichorCNA parameter files are available.

The script extracts:

```text
tumor_fraction
```

from the sample-specific ichorCNA parameter file.

Users who have a different ichorCNA output format should modify this script accordingly.

### Feature Integration Only

`BAM_RDS.R` is responsible for combining the extracted feature objects into:

```r
cfdna_df
```

and saving the data frame as an RDS file.

Users can modify this script when they want to:

* add additional features;
* remove features;
* rename variables;
* change column order;
* save to a different file format;
* change the output location.

For example, the final data frame can be inspected before saving:

```r
head(cfdna_df)
str(cfdna_df)
```

## Feature Groups

The current workflow produces features from several cfDNA characteristics:

| Feature group          | Examples                                | Source                                  |
| ---------------------- | --------------------------------------- | --------------------------------------- |
| Fragment length        | `isize_peak`, `isize_label`, `sl_ratio` | `cfdnakit` / fragment-size distribution |
| 5′ end motif           | `motif_peak_*`, `prop_*`                | `cfdna_feature_2_motif.R`               |
| 3′ end motif           | `motif_peak_*`, `prop_*`                | `cfdna_feature_2_motif.R`               |
| Motif pattern features | `pattern_prop_*`                        | `cfdna_feature_2_motif.R`               |
| Tumour burden          | `ces`                                   | `cfdnakit`                              |
| Tumour fraction        | `tumor_fraction`                        | ichorCNA                                |

## Modifying the Workflow

The workflow is intentionally divided into separate scripts so that individual processing steps can be replaced without rewriting the entire pipeline.

### Common modifications

| If you want to...                      | Modify                      |
| -------------------------------------- | --------------------------- |
| Use a different BAM directory          | `getPath_BAM.R`             |
| Change BAM filtering                   | `read_bamfile.R`            |
| Change genome/bin size                 | `read_bamfile.R`, `utils.R` |
| Change fragment-length definition      | `cfdna_feature_1.R`         |
| Change motif length or position        | `cfdna_feature_2_motif.R`   |
| Use a different tumour-fraction output | `ichorCNA.R`                |
| Add/remove output features             | `BAM_RDS.R`                 |
| Change output file location            | `BAM_RDS.R`                 |
| Change the overall workflow            | `cfDNA_calling.R`           |

When modifying one component, users should check that the variables produced by that script are still compatible with the scripts that use them downstream.

## Reproducibility

For reproducible analysis, users should record:

* R version
* package versions
* genome reference
* BAM filtering parameters
* bin size
* input BAM files
* ichorCNA output used for tumour fraction

## Relationship to Rscript-ML

`Rscript-Main` and `Rscript-ML` represent two separate stages of the analysis.

```text
Upstream sequencing analysis
          |
          v
       BAM files
          |
          v
     Rscript-Main
          |
          v
 cfDNA feature dataset
          |
          v
      Rscript-ML
          |
          +--> Preprocessing
          +--> Feature selection
          +--> Data splitting
          +--> Model training
          +--> Hyperparameter tuning
          +--> Test evaluation
```

**Rscript-Main** converts BAM-level sequencing data into structured cfDNA features.

**Rscript-ML** starts from the resulting feature dataset and performs machine-learning analysis.

Therefore, users who only need the feature-extraction stage can use `Rscript-Main` independently, while users reproducing the complete project can continue from the generated RDS file into `Rscript-ML`.
